## Project Overview

**LazyCv** is an AI-powered interview preparation tool. Users upload their resume (PDF), provide a job description and self-description, and receive a structured interview report (match score, technical/behavioral questions with answers, skill gaps, preparation plan) generated by OpenAI.

## Development Commands

### Backend (run from `Backend/`)
```bash
npm run dev   # nodemon (auto-reload)
npm start     # plain node
```

### Frontend (run from `Frontend/`)
```bash
npm run dev   # Vite dev server at http://localhost:5173
npm run build # Production build
npm run lint  # ESLint
```

Both servers must run simultaneously. The frontend proxies to the backend at `http://localhost:3000`.

## Environment Variables

Backend requires a `.env` file at `Backend/.env`:
```
MONGO_URI=<MongoDB connection string>
JWT_SECRET=<secret for JWT signing>
OPENAI_KEY=<OpenAI API key>
PORT=3000        # optional, defaults to 3000
```

## Architecture

### Backend (`Backend/src/`)

Standard Express layered architecture:

- **`server.js`** — starts the HTTP server, imports `src/app.js`
- **`src/app.js`** — registers middleware (cors, cookie-parser, express.json, multer error handler) and mounts routers
- **`src/routes/`** — route definitions wiring HTTP paths to controllers
- **`src/controllers/`** — request/response handling; calls services and models
- **`src/services/ai.service.js`** — calls OpenAI `gpt-5-nano` with a Zod schema (`zodTextFormat`) to get structured JSON interview reports
- **`src/models/`** — Mongoose schemas: `User`, `InterViewReport`, `Blacklist` (for JWT logout)
- **`src/middleware/auth.middleware.js`** — JWT cookie auth with blacklist check
- **`src/middleware/file.middleware.js`** — Multer memory storage, 3 MB limit for PDF uploads

**API routes:**
- `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`
- `POST /api/interview` — upload resume PDF + body fields → generate & save report
- `GET /api/interview` — list all reports for logged-in user (summary fields only)
- `GET /api/interview/report/:interviewId` — fetch single report by ID

Auth uses **JWT in HTTP-only cookies** (not Authorization header). Logout blacklists the token in MongoDB.

### Frontend (`Frontend/src/`)

Feature-based 4-layer architecture (documented in `notes.md`):

1. **UI** — `pages/` and `components/` (React JSX + SCSS)
2. **Hooks** — `hooks/` — encapsulate state logic and call the API layer
3. **State** — React Context providers wrapping the whole app:
   - `AuthContext` (`features/auth/aut.context.jsx`) — current user, loading state; hydrates from `GET /api/auth/me` on mount
   - `InterviewContext` (`features/interview/interview.context.jsx`) — current report, reports list, loading state
4. **API** — `services/*.api.js` — thin axios wrappers (`withCredentials: true`, base URL `http://localhost:3000`)

**Routes** (defined in `src/app.routes.jsx`):
- `/login`, `/register` — public
- `/` — Home (protected, shows list of past reports + form to create new)
- `/interview/:interviewId` — protected, shows a single interview report

`Protected` component (`features/auth/components/protected.jsx`) reads from `AuthContext` to gate access.

### Key conventions
- SCSS for all styling; global styles in `src/Style.scss`
- `remixicon` for icons
- Resume upload uses `multipart/form-data`; the field name must be `"resume"` (matched by `upload.single("resume")` in the backend)
- The AI service uses `zod` + `zod-to-json-schema` to enforce a strict output schema from OpenAI; `skillGaps` is stored as `Mixed` in Mongoose because the AI occasionally returns a single object instead of an array
